如果我让你按 --ui-scale 为1.1，重新改一下前端，这样怎么样？给出提示词
先说结论，因为这事的收益比看起来小：

烘焙 1.1 只解决三个问题里的一个。 文字在 zoom: 1.1 下本来就是重排版重光栅化的，不糊；位图变软是因为显示尺寸 > 源图尺寸，烘焙进去照样是 1.1 倍上采样，一点没改善。真正修掉的只有 1px 描边和 3px 圆角的非整数取整（细线粗细不均）。代价是 5 个文件、306 个 px 字面量，以及和 design/*.dc.html 画板的 1:1 对应关系断掉——CLAUDE.md 明确写了「数值都是画板里的原值，不要四舍五入」，以后画板改配色改尺寸就没法直接抄了。

另外还有个副作用：13→14 是 +7.7%，9→10 是 +11%，各档舍入率不一致，字阶比例会轻微漂移。

如果你接受这些还是要做，提示词如下：


把 frontend 的 --ui-scale: 1.1 烘焙进所有尺寸值，然后删掉 zoom，让界面在 --ui-scale: 1 下和现在长得一样。

范围：app/assets/css/tokens.css、app/components/SideBar.vue、app/components/AccessGate.vue、
app/pages/index.vue、app/pages/results/[taskId].vue 的全部 px 字面量（约 306 处）。
design/*.dc.html 是设计源，一个字都不要改。

缩放规则：
1. 字号、间距（padding/margin/gap）、宽高、top/left 这类几何量 ×1.1，四舍五入到整数 px。
   已经是 .5 的（12.5px 11.5px 9.5px 10.5px 13.5px）也按 ×1.1 后四舍五入到整数。
2. 以下不缩放，保持原值：
   - 所有 1px / 2px 的 border、outline、分隔线、box-shadow 的偏移 —— 这是本次改动的全部意义所在，
     发丝线必须落在整数设备像素上。
   - --r: 3px、--r-sm: 2px 圆角保持不变（3.3 四舍五入还是 3）。
   - em / % / vh / vw / fr / letter-spacing / line-height 这些相对量，本来就跟着字号走。
   - 图片和视频的容器尺寸照常缩放，但不要动 object-fit 之类。
3. tokens.css 里的 --h-xs/--h-sm/--h/--h-lg/--sidebar/--inspector/--topbar/--ctrlbar 一并按规则 1 处理。
4. 改完把 --ui-scale 设为 1，html { zoom: var(--ui-scale); } 这行保留（留作以后整体缩放的旋钮），
   并把 tokens.css 顶部那段注释改成：数值是画板原值 ×1.1 后取整，画板尺寸 ÷1.1 还原。

验收：
- 起后端 uvicorn 和前端 pnpm dev，用 playwright（channel 'msedge'）分别在
  改动前（--ui-scale: 1.1）和改动后（1）截同样三个页面的图：登录门、任务列表、结果页（含时间轴和缩略图墙），
  1920×1080 视口。逐张肉眼比对，元素位置差异不应超过 1~2px，不允许出现折行变化、
  溢出、滚动条有无翻转。有差异就报出来，不要自己悄悄调数值凑。
- 确认改动后所有分隔线和卡片描边都是均匀 1px（这是收益本身，重点看侧栏、控制条、缩略图卡片描边）。
